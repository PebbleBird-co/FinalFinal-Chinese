# 0010：从扫描基线重放纠正，并固定写入 userData

## 状态

已采纳（Phase 8）

## 决策

用户纠正不直接修改上一次计算结果。应用保留不可变的原始 `ScanResult` 作为基线，每次新增、撤销、重做或手动重算时，都按顺序重放当前 `UserOverride[]`，重新生成家族、版本图、事件、风险和正式版本候选。

最近一次项目状态保存为 Electron `userData/project-state-v1.json`。文件名与目录由主进程固定，Renderer 不能指定保存路径。保存内容包括扫描基线、当前报告和完整撤销/重做历史。

## 理由

- 从基线重放可避免连续修改产生不可逆的累计误差。
- 撤销、重做与重启恢复使用同一种状态模型，行为更容易测试。
- 固定 `userData` 路径不会扩大对用户项目目录的写入权限。
- JSON 足以满足 MVP，不提前引入 SQLite。

## 纠正语义

- 用户确认的父边置信度为 `1`，并替换目标文件原有的自动主父边。
- 跨家族父边和会形成循环的父边会被拒绝。
- “主版本、废弃、副本”对同一文件以最后一次操作为当前有效状态。
- 废弃或副本文件不参与正式版本候选排名，但仍保留在历史关系和风险调查中。
- 拆分与合并家族后，版本图、事件、风险与候选全部重算。

## 范围限制

- 当前只恢复最近一次项目报告，不提供多项目历史列表。
- 持久化只包含元数据和分析结果，不复制或读取文件正文。
- PDF 导出仍属于 Phase 9。
